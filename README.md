# README

# Futari Log(ふたりログ)

## サービス概要
Futari Logは、長く一緒にいるカップルが  
日々の「ごきげん」や「ありがとう」を**ワンタップで記録**し、  
関係性を穏やかに保つためのカップル向けWebアプリです。

言葉にしづらい感情を可視化し、衝突する前の気づきを提供します。

---

## このサービスへの思い・作りたい理由
私自身、パートナーと8年間交際し、同棲生活も1年以上続いています。

長く一緒にいる中で、
- 不満として言うほどではないが、少しモヤっとする瞬間
- 感謝しているのに、わざわざ言葉にしなくなる日常
- 話し合うほどでもないが、気持ちのズレを感じる場面

こうした「小さな感情のズレ」が、積み重なることで関係性に影響することを実感しました。

感情を溜め込まずに済み、かつ相手を責める形にもならない。  
そんな**やさしいコミュニケーションの補助線**となる仕組みがあれば、 
より良い関係を長く続けられるのではないかと思い、このサービスを企画しました。

---

## ユーザー層について
### 想定ユーザー
- 同棲中、または交際歴が長いカップル
- 大きな問題はないが、関係性をより良くしたい人
- 感情を言語化して伝えるのが得意ではない人

### このユーザー層を対象にした理由
- 長期的な関係では「小さな感情の扱い」が重要になるため
- 喧嘩や話し合いを避けたい一方で、気持ちは分かり合いたいというニーズがあるため
- 自身の経験と重なり、課題の解像度が高いと考えたため

---

## サービスの利用イメージ
1. ユーザーはその日の気分をワンタップで記録する
2. 何かしてもらった際に「ありがとう」を簡単に残す
3. 週や月単位で感情の傾向を振り返る
4. 日常の行動を少し意識するきっかけを得る

これにより、  
**感情を溜め込まず、衝突する前に自分と相手の状態に気づける**体験を提供します。

## サービスの差別化ポイント・推しポイント

Futari Logと似た領域のサービスとして、
- カップル向けチャットアプリ（Betweenなど：日常のメッセージやイベント共有が中心）
- 日記・ライフログ系アプリ（Shanfyなど：感情や出来事を文章で記録する設計）

が存在します。

### 既存サービスとの違い(差別化ポイント)

#### 文章を書かせない感情設計
既存のカップル向けアプリでは、日記やメッセージなど、感情を言語化することが求められるケースが多くあります。
一方でFutari Logでは、感情を文章ではなくレベルで記録する設計を採用しています。

これにより、言葉にすると衝突につながりやすい感情でも、心理的負担を抑えて記録することが可能です。

#### 相手を刺激しない可視化
Futari Logでは、感情の詳細な内容を相手にそのまま共有しません。
相手には数値や傾向といった概要のみを表示することで、責め合いや誤解が生まれにくい体験を目指しています。

#### 長期的な関係に特化した設計
恋愛初期の盛り上がりやイベント管理を重視するサービスが多い中で、
Futari Logは同棲中や交際歴が長いカップルを主な対象としています。

日々の小さな感情や感謝を蓄積・振り返ることで、関係性を穏やかに保つことを目的としています。

## 機能候補

### MVPリリース時に実装する機能
- ユーザー登録 / ログイン
- カップル紐付け機能
- ごきげん記録（感情レベルのワンタップ入力）
- 「ありがとう」記録
- 感情・感謝の簡易可視化（週・月単位）

### 本リリースまでに追加する機能
- デフォルトタグ作成
- タグの追加機能
- タグの非表示機能
- カップル解除機能
- パスワードリセット機能(Resend)
- メールアドレス変更機能
- 利用規約・プライバシーポリシー
- 使い方・よくある質問・Futari Logについてページ
- 通知機能

### 今後追加したい機能
- AIによる行動提案機能

## 使用する技術スタック

### フレームワーク
- Ruby on Rails
- Hotwire（Turbo / Stimulus）

### データベース
- PostgreSQL

### デプロイ先
- Render
- Neon

### 使用予定のライブラリ
- Tailwind CSS（レスポンシブ対応）
- Chart.js（感情・感謝の可視化）
- Devise（認証）

### テスト・品質管理（予定）
- Rubocop
- RSpec（モデル・ロジックのテストを中心に実装予定）

### 一般的なCRUD以外の実装予定
- 感情レベルの数値化と集計ロジック
- カップル単位でのデータ共有制御
- 相手を刺激しないための表示制限設計

## 今後の展望

将来的には、記録データをもとにした
